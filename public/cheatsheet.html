Where a block goes

The first word decides.

d1 $ … · hush · setcpsplain Tidal, to the selected engine (GHCi or Architeuthis) both
drums $ …Tidal, played on the drum kit rig
odonus $ …a move for Odonus, or a Review cue rig
v3 $ … · vetula $ ch…a Vetula card, written to the stage rig
conspicillum $ …Conspicillum's line, written to the stage rig
vetula $ mark …a Review cue for Vetula rig

hush

hush · ⌘.stop all sound: both engines, every machine, the ES-9's generators
odonus $ hushone machine: also vetula balistes drums conspicillum selene (its ES-9 signals; the FH-2's run on)
d1 $ silenceone Tidal stream, as in Tidal

Hush silences, clear forgets. odonus $ hush stops the machine, its loops and their patterns, but keeps its marks and record buffer, so odonus $ loop 2 brings a loop straight back. odonus $ clear forgets them.

A hushed machine starts again from its page (Rig, play); drums and Conspicillum also with their next line.

Drums rig

Real Tidal, on the same clock as d1. Each event hits a lane of the drum kit and goes through the drum routing table: Ableton, FH-2 gates, Rample, sample voices.

drums $ s "bd*2 [~ sn] <hh*4 hh*8>" # gain "1 0.7"
drums $ fast "<1 2>" $ s "bd ~ [~ bd] ~, ~ cp, hh*8?" # velocity "0.6 0.9"
drums $ every "<2 3>" (fast 2) $ s "bd [~ sn] hh*2"

Architeuthis's Tidal, a subset that is growing, held to Tidal 1.10.1 case for case: fast, slow, rev, every, scale and the controls.

s "bd"the lane, by name (see below). Unknown names play nothing.
n "36 42"with no s: the MIDI note itself
velocity 0.80..1, the default 0.8; times gain (default 1)
sustain 0.2gate in seconds
legato 1gate as a share of the event; with neither, a 30 ms trigger

Odonus harmony & scale rig

Patterns the rig samples each step to quantise the grid.

odonus $ harmony "<c'maj7 a'min7>/2" # mutate notes 20
odonus $ scale "<dorian mixolydian>/4" # root d
harmony "PATTERN"snap to these notes, read as note reads them
harmony offback to the scale
scale "PATTERN"a pattern of scale names (list below)
scale offback to the scale set by hand
outscale "PATTERN" dsnap the output, past the offsets, to a scale on its own root (instead of harmony's chords)
outscale offthe output back to the grid's scale
root d · root fs · root 2the root, apart from the scale, as in Tidal (C = 0)

Heard only with Odonus on Rig: the rig does the sampling. These lines set Odonus directly; a route (below) says where its sets come from, as the Dashboard's patch bay does.

Harmony routes rig

What shapes Odonus's two quantisations: the same table the Dashboard's patch bay writes, one route a line.

route $ odonus.grid <- vetula 2
route $ odonus.out <- harmony "<c'maj9 a'min11>/2"
route $ odonus.grid <- none
odonus.gridwhat a cell's value maps onto: the melody's shape. A scale; or a chord, whose cells then play its arpeggios, octaves kept (a ninth stays a ninth)
odonus.outwhat each note snaps to at the end, past its head's offset: a chord colours the melody without changing its shape
vetula keyVetula's scale, which may be "outside" its chords
vetula NVetula's voice N: its chords, as voiced. It still sounds where its card sends it
scale "PATTERN" ROOTa pattern of scale names, on a root
harmony "PATTERN"a chord pattern, as voiced
noneno route: Grid follows Odonus's own scale; Output snaps to the Grid's set

Review cues rig

Marks in a machine's record buffer, and loops of them, played by the rig on Link time beside live play. Marks are numbered by position, oldest first, and close up after a delete or a clear; a loop starts on the next downbeat.

vetula $ mark
odonus $ loop 2 # slide "<0 -1 -2>"
odonus|vetula $ markdrop a mark now: its window is that bar and the one before
… $ loop Nloop mark N; several loops can play at once
… $ looploop the latest mark
… $ loop "<1 2>"a pattern of marks, a cycle a bar: each from the top of its window when the pattern reaches it (one such loop a machine)
… $ loop N hushstop loop N
… $ loop hushstop every loop of the machine (… $ hush is the machine)
… $ slide N · widen N · narrow Nmove the window, or its end, by bars
… $ slide "PATTERN" · widen "PATTERN"follow a pattern of bars from the mark; slide off stops following
… $ resetthe window back at its mark, patterns dropped
… $ trimcut everything outside the marks' windows, a bar either side (the surface's ✂ cut takes a stretch you drag across)
… $ undoput back the last cut or trim
… $ clearempty the machine's record buffer: notes, marks, loops (the Review surface's clear does the same)

A window cue acts on the loop its line names (loop 2 # widen 1), else the loop started last, else the latest mark.

Vetula cards rig

A card is one line on the stage. Evaluating v3 $ … rewrites card 3 in Vetula; vetula $ ch… makes a new one. Vetula's λ button sends a card here. Note names are Tidal's: c5 = 60.

v3 $ ch3 "<[c4,e4,g4] [a3,c4,e4] [d4,f4,a4] [g3,b3,d4]>" "0 1 2 3"
  # voice drop2
  # arpup 4 # every 4
  # strum 14

The line

chNMIDI channel, and the card's voice
"<[c4,e4,g4] …>"the chords
"0 1 2 3"mini-notation over chord indices: one cycle a bar. Leave it out for one chord per beat.

Conspicillum rig

The granular cloud's scene as one line. Evaluating it plays it on the Conspicillum page, as if typed in its own line box, so the page must be open. Its → Limulus button brings the line here. Terms are separated by #; anything not said is the default, sixteen grains a bar following the tape.

conspicillum $ s "fd-beat-bar" # walk 0.2 0.1 0.1 # grid 8 # swing 0.62
  # fix snare 0.5 (pshift 1.5) # every 4 0 (speed -1)

Selene: polysignals rig

One line, one bank of eight outputs, all changing on the same instant. A line changes only what it names; the Selene page follows. A single value sets every output, a quoted list sets them in turn and wraps.

selene $ lfo es9main # rate "0.5 1 2 4" # phase "0 0.25"
selene $ euclid es9gt0 # hits 5
selene $ clock es9gt1 # div 1/8 # mult "1 2 3 4 5 6 7 8" # pw 25
